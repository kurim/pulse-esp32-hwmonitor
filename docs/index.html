Flash PulseMQTT straight from your browser.

Pick your board, plug it in over USB, hit install. Then hand it your WiFi and point a PC monitoring script at it — time, weather and live CPU/GPU load, temperature and power land on the display over MQTT or USB/serial.

Open this page on desktop Chrome or Edge. Flashing uses Web Serial, which only runs on a desktop Chromium browser. The rest of this page is just a preview.
00

Before you start

  • Desktop Chrome or Edge. Web Serial doesn't run on Firefox, Safari, or mobile.
  • A real data USB cable. Power-only cables are silent killers - the port simply won't show up.
  • Know your board. CYD (v1/v2), CYD v3, and the JC8048W550 ship with a fixed display; the generic ESP32/S3/C3 images let you wire up your own panel and pick its driver afterwards in the web portal.
  • Installer stuck or can't find the port? Most of these boards auto-reset into the bootloader over USB. If not: hold BOOT, plug in USB while holding, then release - or hold BOOT, tap RESET, then let go of both.
  • Nothing else on the serial port. Close PlatformIO Monitor, Arduino IDE, and the serial monitor below before flashing.

A dialog will ask which serial port to use - pick the one that appears when you plug the board in. The installer erases and writes the full image at offset 0x0; it takes ~30 seconds. Every later update can go through FOTA or a plain .bin upload in the web portal - no repeat USB access needed.

02

Connect to WiFi

Right after flashing, the installer can hand your WiFi straight to the device in this tab - no phone needed. If you miss that window, the device also broadcasts its own setup hotspot you can join from anything. Either way it reboots onto your WiFi.

recommended

Configure WiFi in this tab

When the flash finishes, the install dialog opens a Configure WiFi step. Pick your network, type the password, hit Connect. The credentials travel to the device over USB using Improv Serial - no captive portal, no app switching. This only works on a freshly flashed device (no stored WiFi credentials yet) and stays available as long as the device isn't connected.

  1. Wait for "Installation complete", then keep the dialog open.
  2. Pick your WiFi network and enter the password.
  3. The device joins your WiFi and reboots. Boards with a display show the new IP address on the Settings screen; headless boards need the serial monitor below or your router's client list to find it.
fallback

Or join the setup hotspot

Missed the Configure WiFi dialog, flashed from a phone, or the board has no stored credentials and no USB connection to a browser anymore? Every board falls back to an open setup hotspot named <board>-Setup (e.g. ESP32-2432S028 (CYD)-Setup or Generic ESP32/S3/C3-Setup) that you can join from any device.

setup-mode access point
network <board name>-Setup (open, no password)
portal http://192.168.4.1

Disappears once the device joins your WiFi. On the two boards with Bluetooth WiFi setup (ESP32-S3 8 MB, JC8048W550) Improv-over-BLE is also tried before this fallback kicks in.

  1. Join the <board>-Setup WiFi network from your phone or laptop.
  2. Open 192.168.4.1 and pick your home network, enter the password, save.
  3. The device reboots and joins your WiFi.

After this, the full web portal is reachable any time at the device's IP: MQTT, timezone, weather, display type/rotation/brightness/pin overrides, FOTA - all live there.

03

Feed it hardware data

The device itself doesn't measure anything - it just displays whatever a PC-side script sends it, over MQTT (default) or directly over USB/serial, switchable in the web portal's "Hardware data source" setting. Both paths accept the same JSON, so no separate firmware build is needed either way.

json payload
{
  "cpu_load": 42.5,
  "cpu_temp": 58.0,
  "cpu_power": 65.0,
  "gpu_load": 12.0,
  "gpu_temp": 40.0,
  "gpu_power": 25.0
}

All fields are optional - only the ones present get updated. This repo doesn't bundle a PC agent; send this shape from whatever you already use (LibreHardwareMonitor, HWiNFO, a small Python script, ...) at roughly 1-2 Hz.

mqtt
Published as the retained payload on one topic (default pulsemqtt/hwinfo, QoS 0, MQTT 3.1.1) - set broker host/port/topic in the web portal.
usb
One JSON object per line (\n-terminated) at 115200 baud, over the same USB port used for flashing/logs. No broker or WiFi required for this path.
04

Pick a display

CYD, CYD v3, and the JC8048W550 ship with a fixed panel - nothing to configure here, it just works after WiFi setup. The four generic images (ESP32, ESP32-S3 4 MB/8 MB, ESP32-C3) boot headless by default so a wrong pin never bricks the setup: pick the panel in the web portal instead.

  1. Open the device's IP in a browser, go to the Display card.
  2. Choose GC9A01 (round), ILI9488, ST7796S, SSD1309, or SH1106 from the dropdown.
  3. Default pin wiring is filled in automatically; override any field under "Pin assignment" if you wired it differently - no rebuild or reflash needed.
  4. Save. The device reboots and initializes the selected panel.

A bad pin choice only skips display init and logs a warning - the web portal stays reachable either way to pick again. ESP32-C3 has no PSRAM, so keep an eye on framebuffer size with the larger ILI9488/ST7796S panels.

05

View serial logs

Reading the board's serial output is the fastest way to capture a boot loop, a WiFi error, or a crash for a bug report - and the easiest way to read the IP address on a headless board. Plug the board in over USB, click Connect, and pick the same serial port you'd use for flashing.



          
Only one program can hold the serial port at a time - close PlatformIO / Arduino monitors first, and don't click Install during a monitor session. Baud rate is 115200 to match the firmware.
